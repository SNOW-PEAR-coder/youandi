# youandi

用八字（四柱）看姻缘、感情走势与婚期。这是一个 Codex / Claude Skill，
核心是一个**零依赖的确定性排盘引擎**：干支、节气、大运起运、农历换算全部由天文算法算出，
而不是让模型手工推演。命理断法写在参考文档里，与计算层完全分离。

> 名字说明：skill 的标识名只允许小写字母、数字和连字符（`^[a-z0-9-]+$`），
> 所以 `youandI` 这种驼峰写法无法通过校验、可能导致 skill 加载失败。
> 这里取等价的合法形式 `youandi`，界面显示名仍是 `You and I`。

## 为什么需要一个引擎

LLM 手动排八字有系统性错误，最常见的三类：

1. **立春换年搞错。** 立春前出生的人干支年属上一年。1990-02-03 出生是**己巳（属蛇）**，
   不是庚午（属马）——农历年和干支年在这里是两回事。
2. **漏掉真太阳时。** 经度每偏 1° 差 4 分钟，叠加均时差（±16 分钟）。
   以东经 104° 左右出生为例，真太阳时比北京时间早约 64 分钟，**可能整体落进上一个时辰**。
3. **起运年龄与节气时刻靠猜。** 起运年龄 = 到前一节或后一节的天数 ÷ 3，必须算。

`scripts/bazi.py` 把这些全部做实，模型只需负责断法。

## 安装

作为 Codex skill 使用，把本目录放到 skills 路径下：

```bash
git clone https://github.com/<your-name>/youandi.git ~/.codex/skills/youandi
```

Windows 对应目录为 `%USERPROFILE%\.codex\skills\youandi`。
也可以直接用 `skill-installer` 从仓库路径安装。

## 命令行用法

```bash
# 公历
python scripts/bazi.py --date 1990-06-15 --time 05:30 --gender male --lon 104.1

# 农历（自动换算，闰月加 --leap）
python scripts/bazi.py --lunar 1990-05-23 --time 05:30 --gender male --lon 104.1

# 附带流年扫描
python scripts/bazi.py --date 1990-06-15 --time 05:30 --gender male --lon 104.1 --years 2026-2040

# 机器可读
python scripts/bazi.py ... --json
```

参数：

| 参数 | 说明 |
|---|---|
| `--date` / `--lunar` | 公历或农历生日，`YYYY-MM-DD`，二选一 |
| `--leap` | 农历输入为闰月 |
| `--time` | 出生时刻 `HH:MM`（北京时间），默认 12:00 |
| `--gender` | `male` / `female` |
| `--lon` | 出生地经度（东经为正）。**强烈建议填**，否则不做真太阳时换算 |
| `--day-boundary` | 日柱换日时刻：`23`（子时换日，默认）或 `0`（零点换日） |
| `--years` | 流年扫描范围，如 `2026-2040` |
| `--json` | 输出 JSON |

输出包含：真太阳时与校正量、四柱干支、十神、藏干、日主、月令、空亡、
神煞（姻缘相关的单独标星）、完整大运（方向、周岁、交运／止运日期、与日支和年支的关系）、
流年扫描，以及精度提醒。

## 基准命例

```
公历 1990-06-15 05:30，男，东经 104.1°

   钟表时刻 05:30（北京时间）  ->  庚午 壬午 辛亥 辛卯   （卯时）
   真太阳时 04:26              ->  庚午 壬午 辛亥 庚寅   （寅时）
```

同一钟表时刻、同一日期，用不用真太阳时，时柱从辛卯变成庚寅——这正是本仓库存在的理由。

## 精度与已知限制

- **节气**：Meeus 低精度视黄经级数，残差通常几分钟，最坏约 ±15 分钟。
  出生时刻贴近节气或时辰交界时会自动打印提醒——**这类提示必须如实转达，不要在提醒存在时假装精确。**
- **朔望／农历**：Meeus 新月级数，误差数分钟。已在 2000–2030 全部春节日期上验证为 31/31 正确。
- **ΔT**：Espenak & Meeus 分段多项式，1900–2050 覆盖。
- 曾考虑用 VSOP87 提高节气精度，但完整系数表容易转录出错，而收益只在约 0.07% 的临界命例上体现；
  当前策略是**保留有界误差 + 显式标注临界**。
